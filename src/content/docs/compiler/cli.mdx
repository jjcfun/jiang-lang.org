---
title: Compiler CLI
description: Jiang compiler command-line interface.
---

`jiangc` compiles Jiang source files. The current compiler can emit LLVM IR, object files, or link an executable through the host C compiler.

## Version and Help

```bash
jiangc --version
jiangc --help
```

`--version` prints the Jiang compiler version, host target, and LLVM version.

## Check Only

```bash
jiangc --check tests/samples/minimal.jiang
```

This parses, resolves, and type checks the program without emitting LLVM IR, an object file, or an executable.

## Emit LLVM IR

```bash
jiangc --emit-llvm tests/samples/minimal.jiang
```

By default, LLVM IR is written to standard output. Use `-o` to write it to a file:

```bash
jiangc --emit-llvm tests/samples/minimal.jiang -o minimal.ll
```

## Emit an Object File

```bash
jiangc --emit-obj tests/samples/minimal.jiang -o minimal.o
```

This stops after object generation and does not link an executable.

## Link an Executable

Without an explicit `--emit-*` mode, `jiangc` creates a temporary object file and asks the host `cc` to link an executable:

```bash
jiangc tests/samples/minimal.jiang -o minimal
```

Then run:

```bash
./minimal
echo $?
```

## Debug and Release Modes

`jiangc` defaults to debug mode:

```bash
jiangc --mode debug main.jiang -o main
```

Release mode enables LLVM optimization and uses package-level object organization when compiling a package directory:

```bash
jiangc --mode release . -o app
```

For single-file input, release mode still compiles that source file directly.

## Artifact Cache and Backend Jobs

Debug package builds persist reusable source interfaces and object work products under
`build/cache` by default. Override the location when separate builds must not share a cache:

```bash
jiangc --artifact-cache-dir .jiang-cache . -o app
```

Use the explicit clean command instead of deleting an unresolved path from a script:

```bash
jiangc --artifact-cache-dir .jiang-cache --clean-artifact-cache
```

Independent debug codegen units can run in parallel. The default worker count is the logical CPU
count available to the process; use `--jobs` only to set an explicit limit:

```bash
jiangc --jobs 1 . -o app
```

`--jobs` currently affects debug package object emission. Release, shared-library, LLVM IR, and
single object emission remain serial. A failed unit does not discard successful cached objects, so
a later build can reuse them.

## Targets

Use `--target` for LLVM IR or object output:

```bash
jiangc --target x86_64-unknown-linux-gnu --emit-obj main.jiang -o main.o
```

Hosted executable linking is native-toolchain only. Jiang 0.5.1 supports macOS arm64 and Linux x86_64
as release hosts. Linux hosted programs use the system libc.
Linux aarch64, Wasm, WASI, and Windows targets currently have narrower or experimental output
boundaries, and Linux no-libc executable support is not part of 0.5.1.

## Linker Options

Use `--linker` to select the program used for final linking:

```bash
jiangc --linker /usr/bin/cc main.jiang -o main
```

Pass extra linker arguments with repeated `--link-arg` options:

```bash
jiangc main.jiang -o main --link-arg -lm
```

## Runtime Boundary

Hosted builds use the target host's C runtime and native linker toolchain. Release compilers include
the LLVM libraries used by `jiangc`, so running a packaged compiler does not require a separate
`libLLVM` or `liblld` installation.
