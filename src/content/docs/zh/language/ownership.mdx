Jiang 使用 `T^` 表达拥有所有权的值，使用 `T&` / `T[]&` 表达不拥有资源的借用视图。
这一章集中说明资源如何移动、何时析构，以及引用如何避免悬垂。

## 复制、转移和析构

`Movable` 是默认 auto trait：除非 nominal type 用 `!Movable` 显式退出，否则值可以改变
storage address。`!Movable` 值必须直接初始化到最终 place，不能按值传参、返回、赋给新 place、
捕获或 move。直接 `Task<T>` 和 `Mutex<T>` 用这条规则保持地址稳定。

`Copyable` 继承 `Movable`，决定普通按值使用执行 copy 还是 move。标量、enum、shared reference、
raw pointer 和 `RawFn` 默认 Copyable。用户定义的 `struct` / `union` 不默认 Copyable；
只有显式实现 `Copyable` 且所有字段或 payload 都 Copyable 时才能复制。带自定义 `deinit`
的类型不能实现 `Copyable`。

非 Copyable、但 Movable 的值在赋值、传参、返回和 capture 时默认 move：

```c
Int^ a = new Int(42);
Int^ b = a;

Int value = b$.get();
```

move 后源变量失效：

```c
Int^ a = new Int(42);
Int^ b = a;
Int value = a$.get(); // 错误：a 已经被转移。
```

`$.move()` 仍可作为显式写法，也可以强制 move 一个 Copyable 值：

```c
Int a = 1;
Int b = a;
Int c = b$.move();
Int invalid = b; // 错误：显式 move 已使 b 失效。
```

普通值类型需要显式声明 Copyable：

```c
struct Point: Copyable {
    Int x;
    Int y;
}

Point a = Point(x: 1, y: 2);
Point b = a; // copy
```

普通资源 struct 可以移动但不能复制，因此普通赋值会直接转移：

```c
struct Box {
    Int^ value;
}

Box a = Box(value: new Int(1));
Box b = a; // move；a 随后失效
```

runtime 析构取决于 ownership、字段、payload 和自定义 `deinit`，不由 `Movable` 标记开启。
`T^` 会先析构 pointee，再释放堆存储。tuple、array、optional、errorable、struct 和 union
会递归析构拥有的内容。`T&`、`T*`、`T[]&` 等非拥有视图不会释放目标。自定义 `deinit`
先执行，随后字段按声明逆序析构。

## 引用规则

引用不拥有目标对象。创建引用时，引用的使用范围不能超过被引用的值：

```c
Int value = 10;
Int& ref = value$.ref();
Int copied = ref$.get();
```

普通局部变量使用 `.ref()` / `.mut_ref()` 创建引用。`ref` / `ref!` 只用于解构、
承载值模式和 lambda capture：

```c
Int value = 10;
Int& ref = value$.ref();

Int first! = 20;
Int&! mutable_ref = first$.mut_ref();

Int second! = 30;
Int&! another_mutable_ref = second$.mut_ref();

(ref borrowed) = value;
(ref! another_borrow) = second;
```

在可选值和联合的承载值模式中，使用 `ref name` 借用承载值，不会隐式复制或转移。
省略的类型位表示 `_`；需要显式 type pattern 时仍可写 `ref T name`：

```c
Int read_ref(Int& value) {
    value$.get()
}

Int read_optional(Int? value) {
    if value is .some(ref Int item) {
        return read_ref(item);
    }
    return 0;
}
```

返回局部变量引用是不允许的，因为函数返回后局部变量已经不存在：

```c
Int& bad_ref() {
    Int value = 10;
    return value$.ref(); // 错误：返回值引用了局部变量。
}
```

全局变量也可以被借用，但全局借用不会得到特殊的 static 生命周期。它仍然是普通借用，
必须停留在当前调用栈内：

```c
Int global_value = 10;

Int read_ref(Int& value) {
    value$.get()
}

Int read_global() {
    return read_ref(global_value$.ref()); // 允许：在这次调用中消费。
}

Int& bad_global_ref() {
    return global_value$.ref(); // 错误：全局借用不能作为 static 引用逃逸。
}
```

如果全局值需要被其他模块访问，使用 `public`。不要为了暴露全局值而返回它的借用。

如果某个接口看起来需要静态生命周期，优先直接使用全局变量名，或者提供函数在每次调用时
临时取得局部借用：

```c
public Int global_limit = 10;

Int current_limit() {
    global_limit
}

Int read_limit_ref() {
    return read_ref(global_limit$.ref());
}
```

如果要返回一个值，直接返回值本身：

```c
Int make_value() {
    Int value = 10;
    return value;
}
```

如果要返回一个堆上对象的所有权，返回 `T^`：

```c
Int^ make_owner() {
    return new Int(10);
}
```

Jiang 区分 shared readonly loan 和 unique mutable loan。任意数量的 shared `T&` view 可以共存。
`T&` 本身不提供写能力，但普通 shared view 不会仅因存在就冻结 owner 通过自身更新 source。
live `T&!` 必须对所有重叠 place 保持独占，且不能隐式复制；这种 unique loan 存活期间，
与 source 重叠的 storage 不能被覆盖、move 或 drop。

把 `T&!` reborrow 为 `T&` 会创建 frozen shared view。原 unique reference 仍可读取，但在 shared
reborrow 最后一次使用前不能写入；多个 shared reborrow 可以同时存在。

loan 使用 non-lexical lifetime：最后一次可达使用之后即可结束，因此可以顺序 mutable reborrow。
struct sibling field 与不同 constant array index 可分别借用；dynamic index 和 subslice 保守视为重叠。

async 调用捕获 borrow 时，直接创建的结构化 Task 会持有 loan，直到 Task 完成且作用域清理结束。
`cancel()` 只发布取消请求；需要等待终态时应使用 `await()` 或 `cancel_and_await()`。跨作用域或
Domain 的 heap Task 仍必须满足普通 lifetime 与 `Sendable` 规则。

跨 Domain 传递和 lifetime 有效性是两项独立检查。当 `T: Sendable` 时，共享 `T&` 可以作为参数、
返回值或 capture 跨 Domain，但仍不能活过来源 owner。`T&!` 不能直接跨 Domain；需要 `T&` 的
调用可以建立上面的 frozen shared reborrow。raw pointer 不携带 ownership 或 lifetime 证明，
不会自动满足 `Sendable`。

## 生命周期约束

包含借用的 `struct` / `union` 使用 `@region` 声明公开 lifetime region。每个 region 都必须被字段或
union payload 使用。引用同时包含外层 borrow 与 pointee 的 lifetime shape。对于简单字段，
`@life(a)` 会绑定外层 borrow，并用 `a` 填充 pointee 的全部 lifetime：

```c
@region(a)
struct ByteView {
    @life(a)
    UInt8[]& data;
    Int length;
}
```

使用位置绑定时，region 的声明顺序有意义。`@region(a, b, b: a)` 表示 `a` 至少要和 `b`
活得一样久。关系两端必须在同一个 annotation 中声明，同一个名字不能被约束两次。
允许相互约束：`@region(a, b, b: a, a: b)` 表示 `a` 和 `b` 的生命周期要求相同。

具有多个 lifetime 的字段可以按声明顺序写 `@life(a, b)`，也可以使用字段类型提供的名字，
写成 `@life(left: a, right: b)`。两种形式不能混用，每个名字必须恰好绑定一次；
字段绑定不能使用 `self`。

需要精确绑定一个 pointee 带多个 region 的引用时，pointee shape 必须保持分组。假设 `PairRef` 有
`left`、`right` 两个 region，应写 `@life(a, (left, right))`，不能扁平化成
`@life(a, left, right)`，也不能只绑定其中一个 pointee region。

泛型 region 必须显式写明来源类型。`a: T` 表示 `a` 具有 `T` 的完整 lifetime shape；`= anchor`
表示字段省略该泛型绑定时，用 `anchor` 填充全部 slot：

```c
@region(anchor, value: T = anchor)
struct BorrowedBox<T> {
    @life(anchor)
    T& value;
}
```

类型直接存储 `T` 时使用 `@region(a: T)`。泛型参数必须出现在成员类型中；Jiang 不允许 phantom
nominal 类型参数。

函数和方法统一使用 `target: source`：右侧名字代表的借用必须比左侧名字代表的值活得更久：

```c
@life(return: data)
UInt8[]& first_two(UInt8[]& data) {
    return data[0..2];
}
```

返回值包含借用但省略 `@life` 时，readonly `self` / `Self&! self` receiver 默认作为来源。
没有这种 receiver 时，如果只有一个参数携带借用，就默认使用该参数。一个参数即使携带多个
lifetime，也仍然只算一个参数。这条规则只根据函数声明确定，不会分析函数体选择了哪个分支：

```c
Int& first(Int& value) {
    return value; // 默认等价于 @life(return: value)
}

struct Pair {
    Int left;
    Int right;

    Int& choose(self, Bool use_left) {
        if use_left {
            return self.left$.ref();
        }
        return self.right$.ref(); // 默认等价于 @life(return: self)
    }
}
```

`Self self` 按值 receiver 不享受优先级，和普通参数一样处理。没有参数携带借用时，必须用
`@life()` 确认返回值不借用参数；有多个参数携带借用，或者来源与返回值的 lifetime 位置不一致
时，必须显式写 `@life`。显式 annotation 会定义全部允许的 lifetime 关系，不再补充默认关系。
同一个左侧名字只能出现一次；返回值可能借用多个兼容来源时，使用 `&`：

```c
@life(return: left & right)
Int& pick(Int& left, Int& right, Bool use_left) {
    if use_left {
        return left;
    }
    return right;
}
```

参数之间也使用相同语法。`@life(left: right)` 表示 `right` 中每个借用部分都必须比 `left`
中对应的借用部分活得更久：

```c
@life(left: right)
Void relate(Int& left, Int& right) {}
```

返回值包含多个 lifetime 时，使用元组表达式一次映射完整的 `return`：

```c
@region(a, b)
struct PairRef {
    @life(a)
    Int& left;

    @life(b)
    Int& right;
}

@life(return: (left, right))
PairRef make_pair(Int& left, Int& right) {
    PairRef(left: left, right: right)
}
```

不能把它拆成 `return.a` / `return.b` 多条映射，也不能重复同一个左侧名字。`@life` 不支持
`value[0]` 位置路径；tuple 元素和 `Fn` / `RawFn` 的 result/参数位置必须命名后才能引用。
`@life()` 明确表示没有来自参数的 lifetime 关系。

callable 的 lifetime 关系使用它声明的 result 和参数名：

```c
@life(callback.result: callback.value, return: value)
Int& apply(Fn<Int& result, Int& value> callback, Int& value) {
    callback(value)
}
```

如果没有足够长的输入生命周期，应该返回拥有所有权的值，而不是返回引用视图。
