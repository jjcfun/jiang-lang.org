Jiang 使用 `T^` 表达拥有所有权的值，使用 `T&` / `T[]&` 表达不拥有资源的借用视图。
这一章集中说明资源如何移动、何时析构，以及引用如何避免悬垂。

## 复制、转移和析构

`Movable` 是默认 auto trait：除非 nominal type 用 `!Movable` 显式退出，否则值可以改变
storage address。`!Movable` 值必须直接初始化到最终 place，不能按值传参、返回、赋给新 place、
捕获或 move。直接 `Task<T>` 和 `Mutex<T>` 用这条规则保持地址稳定。

`Copyable` 继承 `Movable`，决定普通按值使用执行 copy 还是 move。标量、enum、shared reference、
raw pointer 和 `RawFn` 默认 Copyable。用户定义的 `struct` / `union` 不默认 Copyable；
只有显式实现 `Copyable` 且所有字段或 payload 都 Copyable 时才能复制。带自定义 `deinit`
的类型不能实现 `Copyable`。

非 Copyable、但 Movable 的值在赋值、传参、返回和 capture 时默认 move：

```c
Int^ a = new Int(42);
Int^ b = a;

Int value = b$.get();
```

move 后源变量失效：

```c
Int^ a = new Int(42);
Int^ b = a;
Int value = a$.get(); // 错误：a 已经被转移。
```

`$.move()` 仍可作为显式写法，也可以强制 move 一个 Copyable 值：

```c
Int a = 1;
Int b = a;
Int c = b$.move();
Int invalid = b; // 错误：显式 move 已使 b 失效。
```

普通值类型需要显式声明 Copyable：

```c
struct Point: Copyable {
    Int x;
    Int y;
}

Point a = Point(x: 1, y: 2);
Point b = a; // copy
```

普通资源 struct 可以移动但不能复制，因此普通赋值会直接转移：

```c
struct Box {
    Int^ value;
}

Box a = Box(value: new Int(1));
Box b = a; // move；a 随后失效
```

runtime 析构取决于 ownership、字段、payload 和自定义 `deinit`，不由 `Movable` 标记开启。
`T^` 会先析构 pointee，再释放堆存储。tuple、array、optional、errorable、struct 和 union
会递归析构拥有的内容。`T&`、`T*`、`T[]&` 等非拥有视图不会释放目标。自定义 `deinit`
先执行，随后字段按声明逆序析构。

## 引用规则

引用不拥有目标对象。创建引用时，引用的使用范围不能超过被引用的值：

```c
Int value = 10;
Int& ref = value$.ref();
Int copied = ref$.get();
```

在局部绑定中，`ref _` 会创建推导 pointee 类型的 shared borrow。standalone mutable borrow
使用 `ref!` 或 `mut_ref()` 从可写 place 创建唯一可变 `T&!` 借用：

```c
Int value = 10;
ref _ ref = value; // 生命周期规则等同于 value$.ref()

Int first! = 20;
ref! _ mutable_ref = first;

Int second! = 30;
Int&! another_mutable_ref = second$.mut_ref();
```

在可选值和联合的承载值模式中，使用 `ref T name` 借用承载值，
不会隐式复制或转移承载值。`ref` 后面需要写出类型，也可以写 `_` 类型占位：

```c
Int read_ref(Int& value) {
    value$.get()
}

Int read_optional(Int? value) {
    if value is .some(ref Int item) {
        return read_ref(item);
    }
    return 0;
}
```

返回局部变量引用是不允许的，因为函数返回后局部变量已经不存在：

```c
Int& bad_ref() {
    Int value = 10;
    return value$.ref(); // 错误：返回值引用了局部变量。
}
```

全局变量也可以被借用，但全局借用不会得到特殊的 static 生命周期。它仍然是普通借用，
必须停留在当前调用栈内：

```c
Int global_value = 10;

Int read_ref(Int& value) {
    value$.get()
}

Int read_global() {
    return read_ref(global_value$.ref()); // 允许：在这次调用中消费。
}

Int& bad_global_ref() {
    return global_value$.ref(); // 错误：全局借用不能作为 static 引用逃逸。
}
```

如果全局值需要被其他模块访问，使用 `public`。不要为了暴露全局值而返回它的借用。

如果某个接口看起来需要静态生命周期，优先直接使用全局变量名，或者提供函数在每次调用时
临时取得局部借用：

```c
public Int global_limit = 10;

Int current_limit() {
    global_limit
}

Int read_limit_ref() {
    return read_ref(global_limit$.ref());
}
```

如果要返回一个值，直接返回值本身：

```c
Int make_value() {
    Int value = 10;
    return value;
}
```

如果要返回一个堆上对象的所有权，返回 `T^`：

```c
Int^ make_owner() {
    return new Int(10);
}
```

Jiang 区分 shared readonly loan 和 unique mutable loan。任意数量的 shared `T&` 可以共存；
live `T&!` 必须对所有重叠 place 保持独占，且不能隐式复制。任意 reference loan 存活期间，
与 source 重叠的 storage 都不能被覆盖、move 或 drop。

loan 使用 non-lexical lifetime：最后一次可达使用之后即可结束，因此可以顺序 mutable reborrow。
struct sibling field 与不同 constant array index 可分别借用；dynamic index 和 subslice 保守视为重叠。

async 调用捕获 borrow 时，直接创建的结构化 Task 会持有 loan，直到 Task 完成且作用域清理结束。
`cancel()` 只发布取消请求；需要等待终态时应使用 `await()` 或 `cancel_and_await()`。跨作用域或
Domain 的 heap Task 仍必须满足普通生命周期与 `Sendable` 规则。Domain scheduling 不会放宽
shared/unique 规则，因此安全引用在 serial 与 concurrent Domain 间仍保持 data-race freedom。

## 生命周期约束

nominal `struct` / `union` 使用 `@region` 声明公开 lifetime Shape。每个 region 都必须直接
绑定到至少一个字段或 union payload 的 lifetime slot。单-slot 字段使用 `@life(a)`：

```c
@region(a)
struct ByteView {
    @life(a)
    UInt8[]& data;
    Int length;
}
```

public region 按稳定 Shape 顺序声明。`@region(a, b, b: a)` 表示 `a` outlives `b`。
约束两端必须在同一 annotation 中声明，同一个 constraint target 不能出现两次。coverage
允许成环：`@region(a, b, b: a, a: b)` 表示两个 region 互相覆盖。每个 region 都必须被
实际字段或 payload slot 使用。

多-region 字段可以按 Shape 位置写 `@life(a, b)`，也可以按字段类型公开的名字写
`@life(left: a, right: b)`。两种模式不能混用，每个 target 必须恰好绑定一次；
字段 binding 不能使用 `self` source。

函数和方法统一使用 `target: source`，右侧 source 覆盖左侧 target：

```c
@life(return: data)
UInt8[]& first_two(UInt8[]& data) {
    return data[0..2];
}
```

函数返回 Shape 非空但省略 `@life` 时，Shape 非空的 readonly `self` / `Self&! self`
reference receiver 优先成为默认来源。没有 receiver 特例时，只有恰好一个用户可见参数 root
携带 lifetime，才使用该参数的完整 Shape；单个多-region 参数仍只算一个 root。这是
signature elision，不是从函数体推断：

```c
Int& first(Int& value) {
    return value; // 默认契约：@life(return: value)
}

struct Pair {
    Int left;
    Int right;

    Int& choose(self, Bool use_left) {
        if use_left {
            return self.left$.ref();
        }
        return self.right$.ref(); // 默认契约：@life(return: self)
    }
}
```

`Self self` 按值 receiver 不享受优先级，只参与普通的唯一 root 规则。零个非空输入 root 时，
必须用 `@life()` 确认返回值不携带参数 borrow；存在两个或更多 root，或唯一 root 与 return
Shape 不兼容时，必须显式声明。任意显式 `@life(...)` 都完全替换 implicit return contract。
每个 target 必须唯一；同 Shape 的多个候选来源使用 `&` 逐位取得共同最短 region：

```c
@life(return: left & right)
Int& pick(Int& left, Int& right, Bool use_left) {
    if use_left {
        return left;
    }
    return right;
}
```

参数 target 表示参数声明的完整 Shape，不是参数栈槽。`@life(left: right)` 要求 `right`
按 Shape 位置覆盖 `left`，函数体检查和每个调用点都必须满足：

```c
@life(left: right)
() relate(Int& left, Int& right) {}
```

多-slot 返回值必须把完整 `return` target 一次映射到 product expression：

```c
@region(a, b)
struct PairRef {
    @life(a)
    Int& left;

    @life(b)
    Int& right;
}

@life(return: (left, right))
PairRef make_pair(Int& left, Int& right) {
    PairRef(left: left, right: right)
}
```

不能把它拆成 `return.a` / `return.b` 多条映射，也不能重复同一个 target。lifetime contract
不支持 `value[0]` 位置路径；tuple 元素和 `Fn` / `RawFn` 的 result/参数位置必须命名后才能引用。
`@life()` 表示显式空 callable contract。

callable 子契约使用它声明的 result 和参数名：

```c
@life(callback.result: callback.value, return: value)
Int& apply(Fn<Int& result, Int& value> callback, Int& value) {
    callback(value)
}
```

如果没有足够长的输入生命周期，应该返回拥有所有权的值，而不是返回引用视图。
