需要在程序运行前就确定的值，可以写成 `const`：固定尺寸、功能开关、目标信息、共享配置等都
适合用它表达。`comptime { ... }` 显式执行编译期计算；根据目标选择模块时，使用 alias 接收导入表达式。

## Const 声明

`const` 可以显式标注类型，也支持从初始化结果推导类型：

```c
const Int page_size = 4096;
const Bool tracing_enabled = false;
```

const initializer 当前支持字面量、其他 `const`、枚举 case、tuple/array/struct 字面量、默认
struct constructor、字段访问、一元和二元表达式、`if`、block 尾表达式、普通 Jiang 函数调用、
自定义 `init`，以及所有参与值都能在编译期确定时的泛型函数或泛型 struct constructor 调用。

const initializer 不能依赖运行时值，也不能执行 I/O 这类运行时副作用。

## 公开常量

`public const` 会让其他模块也能访问这个编译期值。它适合用来共享配置和目标描述：

```c
public enum Os {
    macos,
    linux,
    unsupported,
}

public struct TargetInfo {
    public Os os;
    public Bool link_libc;
}

public const TargetInfo target = TargetInfo(os: .macos, link_libc: true);
```

导入方通过模块命名空间访问：

```c
alias cfg = import "config.jiang";

Bool uses_libc() {
    cfg.target.link_libc
}
```

导入方像访问其他 public 成员一样使用它。public const 可以是标量、枚举 case、tuple、array 或
struct 值；如果它是 struct，也可以直接读取字段。

## 构建目标信息

`build` 包提供当前构建目标的编译期信息：

```c
import build;

const Bool native_libc = build.target.link_libc;
```

`build.target` 包含 `os`、`arch`、`abi` 和 `link_libc` 等字段。需要让代码随目标平台变化时，
可以在常量、普通表达式或 `comptime` 条件里使用这些字段。

## 编译期代码块

`comptime { ... }` 在编译期执行并返回块结果。块有自己的词法作用域，内部绑定不会发布为模块声明。
条件导入通过 alias 接收选中的 namespace，alias 初始化隐式在编译期执行：

```c
import build;

alias provider = if (build.target.os == .macos) {
    import "os/macos.jiang"
} else {
    import "os/other.jiang"
};
```

条件必须是编译期 `Bool`，只有选中的 import 进入依赖闭包；未选分支仍需符合语法。
编译期可以调用操作受求值器支持的普通函数，不需要单独的 comptime 函数标记。

## 编译期泛型参数

编译期泛型参数让声明接收一个编译期值：

```c
struct StaticCount<N: const Int> {
    Int value;
}

Int const_value<N: const Int>() {
    N
}
```

参数名属于值层，可以出现在需要编译期值的表达式里；它不是类型名。

`@where(N: const Int)` 是 canonical constraint 形式；inline `N: const Int` 会 lower 到同一 predicate。
