自定义语法是 Jiang 实现 All in one 的基石。用户可以基于自己的理想语法扩展 Jiang，
同时继续享受 Jiang 自带的类型检查和系统级运行效率。

它让一个包在特定位置接管一段源码的解析，再把结果交还给 Jiang 编译器继续做名字解析、
类型检查和代码生成。它适合表达查询语句、界面、着色器、协议、低层汇编片段等领域语法。

当前实现支持块形式：

```c
User user = #sql {
    select * from User where id == \(id)
};
```

`#sql` 中的 `sql` 不是普通变量名，也不通过 `import` 查找。它通常来自当前包描述文件里的依赖别名。
编译器也可以提供内建语法块，例如 `#asm`。

## 代表性场景

下面的片段是自定义语法的方向草图，用来展示它适合解决的问题；具体语法由对应语言包定义。

对象关系查询可以把表、字段和插值参数一起纳入检查：

```c
User[] users = #query {
    from User
    where age >= \(min_age)
    select id, name, email
};
```

界面模板可以保留接近 HTML 的结构，同时让组件、属性和绑定表达式回到 Jiang 类型系统：

```c
View profile = #html {
    <section class="profile">
        <h1>{user.name}</h1>
        <button on_click={save(user.id)}>Save</button>
    </section>
};
```

声明式界面可以使用更接近 SwiftUI 的树形写法，由语言包检查组件参数、状态绑定和事件签名：

```c
View settings = #ui {
    VStack(spacing = 12) {
        Text("Settings").font(.title)
        Toggle("Enable cache", is_on = bind(settings.cache_enabled))
        Button("Save") {
            save(settings)
        }
    }
};
```

图形着色器可以使用贴近图形领域的写法，再由语言包生成宿主侧可检查的入口和资源绑定：

```c
Shader blur = #shader {
    texture source: Texture2D<Float4>;
    uniform radius: Float;

    fragment Float4 main(Float2 uv) {
        return sample_blur(source, uv, radius);
    }
};
```

向量计算可以把批量运算写成清晰的数学表达式，由语言包选择合适的向量指令或普通后端路径：

```c
Vec4 result = #simd {
    let a = load4(lhs);
    let b = load4(rhs);
    fma(a, b, bias)
};
```

二进制协议可以把字段编号、字节序、长度关系和可选字段集中描述，生成高效的编码和解码代码：

```c
Codec<User> user_codec = #binary {
    message User {
        1: UInt64 id;
        2: UInt8[]& name;
        3: UInt8[]&? email;
    }
};
```

状态机或协议流程可以显式写出状态迁移，让语言包检查遗漏分支和非法转移：

```c
StateMachine connection = #state {
    disconnected -> connecting on connect;
    connecting -> connected on ready;
    connected -> disconnected on close;
};
```

命令行参数可以用声明式结构描述，再生成解析、帮助文本和类型安全的配置对象：

```c
CliOptions options = #cli {
    command build {
        flag release: Bool = false;
        option target: Target = native;
        arg input: Path;
    }
};
```

服务路由可以把路径参数、请求体和返回值集中描述，让路由处理函数保留静态类型：

```c
Router api = #route {
    GET /users/:id -> get_user(id: UserId) -> User;
    POST /users -> create_user(body: NewUser) -> User;
};
```

数据管线可以显式描述步骤和依赖关系，由语言包检查输入输出类型是否能衔接：

```c
Pipeline image_pipeline = #pipeline {
    load(path)
        |> decode_png
        |> resize(width = 256, height = 256)
        |> encode_webp(quality = 90)
};
```

寄存器和位域可以贴近硬件手册描述地址、权限和字段宽度，再生成低层访问代码：

```c
RegisterBlock uart = #mmio {
    base 0x4000_1000;
    reg control: UInt32 offset 0x00 {
        enable: bit 0 read_write;
        mode: bits 1..2 read_write;
    }
    reg status: UInt32 offset 0x04 read_only;
};
```

## 内建汇编块

`#asm` 是内建语法块，用来在 Jiang 函数中写少量目标平台汇编。
它适合实现系统调用、启动代码、特殊指令或极少数后端暂时不能直接表达的操作。

```c
Int linux_syscall1(Int number, Int arg0) {
    return #asm {
        result Int;
        code "syscall";
        in "rax" number;
        in "rdi" arg0;
        out "rax";
        clobber "rcx";
        clobber "r11";
        memory;
        volatile;
    };
}
```

也可以把汇编块写成语句。当不需要返回值时，可以省略 `result`：

```c
Void fence() {
    #asm {
        code "mfence";
        memory;
        volatile;
    }
}
```

`#asm` 是短名，用户可以用自己的语言包覆盖这个名字。需要明确使用编译器内建版本时，
可以写完整路径：

```c
Int linux_syscall1_builtin(Int number, Int arg0) {
    return #jiang.asm {
        result Int;
        code "syscall";
        in "rax" number;
        in "rdi" arg0;
        out "rax";
        clobber "rcx";
        clobber "r11";
        memory;
        volatile;
    };
}
```

当前 `#asm` 支持这些条目：

- `result T;`：汇编块的返回类型；省略时返回空值。
- `code "...";`：汇编文本，必须提供。
- `in "寄存器或约束" value;`：输入操作数。
- `out "寄存器或约束";`：输出操作数。
- `clobber "寄存器或资源";`：声明会被破坏的寄存器或资源。
- `memory;`：声明汇编会读写普通内存。
- `volatile;`：声明汇编有副作用，编译器不能随意删除或重排。
- `noreturn;`：声明汇编不会返回。

汇编语法本身依赖目标平台。`rax`、`rdi`、`syscall` 这类名字只适用于特定处理器和操作系统。
普通业务代码不建议使用 `#asm`；它主要服务于运行时、系统接口和极少数性能或平台边界代码。

## 文档注释

使用 `///` 为声明添加文档。连续多行会组成一份 Markdown 文档：

```c
/// 返回两个整数之和。
/// 两个参数直接相加，不进行转换。
public Int add(Int left, Int right) {
    return left + right;
}
```

`#doc` 用于多行文档块，header 独占一行，以独占一行的 `#end` 结束。
`#doc(module)` 必须放在第一个非 import 声明之前，用于描述当前模块：

```c
#doc(module)
Collection 工具。
#end

#doc
    ## Vector

    使用连续内存保存元素。
#end
public struct Vector<T> {
}
```

文档可以通过反射读取，供文档生成器和 LSP 悬停提示使用。
lang dependency 可以覆盖 `#doc`；需要明确选择内建 provider 时使用 `#jiang.doc`。
`///` 始终使用内建文档 provider。

## 整文件集成

自定义语言支持独立源文件。配置扩展名映射后，普通 import 会调用对应的 Lang provider，
将文件解析为 Jiang 模块：

```c
alias schema = import "user.proto";
alias layout = import "dashboard.ui";
alias kernel = import "blur.shader";

User user = schema.User(id = 1, name = "Jiang");
View page = layout.render(user);
```

这样外部语言文件不是独立的生成步骤，而是包依赖图的一部分。字段、函数、资源和生成类型仍能继续进入
Jiang 的名字解析、类型检查和后端优化。

## 脚本语言嵌入

Jiang 语言本身围绕所有权和生命周期设计，默认不要求垃圾回收。后续如果引入垃圾回收机制，也应该是
可选运行时能力：用户和包可以按场景决定是否启用。自定义语法可以在这种可选运行时上承载脚本语言，
让脚本片段或脚本文件作为 Jiang 包的一部分接入，适合游戏逻辑、插件、热更新规则和用户自动化：

```c
Script startup = #script {
    let player = world.find("player")
    player.inventory.add("key")
    on event.dialog_finished {
        world.open_door("north_gate")
    }
};
```

脚本侧可以使用更动态的对象模型，宿主侧仍由 Jiang 描述资源、边界类型和调用接口。这样脚本语言获得
更灵活的表达方式，而关键路径仍可以留在 Jiang 的所有权和生命周期模型中，保留系统级运行效率。

## 使用语言包

使用方在 `package.jiang` 中声明一个依赖：

```c
#package {
    name = "app";
    root = "src/main.jiang";
    dependencies {
        sql = "../sql_lang";
    }
}
```

被调用的依赖包需要声明为语言包：

```c
#package {
    name = "sql_lang";
    root = "lang.jiang";
    type = .lang;
}
```

语言包根模块用 `@entry(lang)` 标记可无参数构造、实现 `std.jiang.syntax.Provider` 的具体类型。
类型名称任意，可以保持私有。
使用方通过配置的语言别名调用它。

## 语法提供者

语法提供者实现 `std.jiang.syntax.Provider`。采用 Jiang 默认词法规则时，只需实现 `parse`：

```c
import std;

@entry(lang)
struct Provider: std.jiang.syntax.Provider {
    public std.jiang.syntax.Ast parse(
        Self&! self,
        std.jiang.syntax.Input input,
        std.jiang.syntax.SyntaxContext<std.jiang.syntax.EmptyLangContext>& syntax
    ) {
        _ parser! = std.jiang.syntax.default_parser(syntax.syntax, input);
        std.jiang.syntax.Expr value = parser.int_literal(input.name_span, "0");
        return parser.ast(value);
    }
}
```

默认 `scan` 能识别嵌套 delimiter、字符串、注释和文件结尾。需要自定义 token 时，provider 可以覆盖
`scan`，在自己的实例中保存 `Token<CustomKind>`，再在 `parse` 中构造 `Parser<CustomKind>`。

Parser 方法生成带类型角色的 expression、statement、declaration、type、pattern 和 attribute handle。
`parser.ast(handle)` 返回解析结果。返回的角色必须符合使用位置：表达式位置返回表达式，
顶层返回声明，类型内部返回成员。

## 语言别名与文件扩展名

先统一注册依赖，再配置语言别名：

```c
#package {
    dependencies {
        tools = "../schema-tools";
    }
    lang schema {
        package = tools;
        extensions = ["schema", "model"];
    }
}
```

使用 `#schema { ... }` 或导入 `models.schema`。Provider 包可用 `lang { extensions = ["schema", "model"]; }` 声明默认扩展名；
使用方的配置整组覆盖该列表。没有显式列表时，默认扩展名与语言别名相同，`.jiang` 保留原生语法。
整文件 Provider 收到 `.none` 分隔符并返回声明，文件也可以作为 package root。
源码内容、扩展名映射和 Provider 依赖共用编译器缓存。

一个包可以同时提供 Lang 与[生成入口](/zh/language/generation/)。使用语言别名选择生成器时，
显式的同名 generate 配置优先。

## 共享关键词与上下文

无状态 Provider 可以使用默认的 `EmptyLangContext`，只实现 `parse`。需要共享关键词等数据时，
声明关联类型 `LangContext`，用 `create_context(Session&)` 初始化，通过 `context.lang` 只读访问。
同一语言在一次编译中共享上下文，不同编译互相隔离；每个块仍有独立的 Provider 实例。
不要把某个块的 token 或临时解析状态放进共享上下文。

下面的语言接受 `#value { value 42 }`，也接受省略关键词的 `#value { 42 }`：

```c
import std;

public struct Keywords: Copyable {
    std.jiang.syntax.SymbolId value;
}

@entry(lang)
struct ValueProvider: std.jiang.syntax.Provider {
    public associated LangContext = Keywords;

    @life()
    public Keywords create_context(std.jiang.syntax.Session& session) {
        return Keywords(value = session.intern("value"));
    }

    public std.jiang.syntax.Ast parse(
        Self&! self, std.jiang.syntax.Input input,
        std.jiang.syntax.SyntaxContext<Keywords>& context
    ) {
        _ parser! = std.jiang.syntax.default_parser(context.syntax, input);
        parser.match_keyword(context.lang.value);
        _ value = parser.parse_expression();
        return parser.ast(value);
    }
}
```

`session.intern()` 的结果可直接与默认 token 比较，不需要每个块重新注册关键词。

## 嵌套语言与 Attribute

默认 parser 遇到 RawBlock 时，调用 `parser.parse_raw_block()`，得到 `Ast?`。
使用 `role()` 或 `as_attribute()`、`as_decl()`、`as_member()` 等方法检查结果。
因此你的语言可以接收 `#doc`，不必识别名称或实现 Markdown 解析。

返回 Attribute 后，由外层语言决定附着目标，并通过 `with_attributes` 附着到 Decl 或 Member。
尚未遇到目标时，可以先保存在 `parser.list<Attribute>()` 中。块末尾仍有待附着内容时应报错，
不要把内部块的文档自动附着到外部声明。包配置字段之间的 Attribute 则允许忽略。

`parser.ast(member)` 返回单个成员，`parser.members(span, values)` 返回成员序列；
声明序列使用 `parser.declarations(span, values)`。空序列和单元素序列仍是序列，
可以通过 `parser.len(sequence)`、`parser.at(sequence, index)` 读取。

当前位置不是 RawBlock 时，展开返回 null 并报诊断，不消费 token；如果 RawBlock 展开失败，
该 token 已消费，诊断保留。`peek`／`advance` 只读取 token，不自动展开语言块。

自定义 tokenizer 可在 `begin_token()` 后使用 `scan_raw_block()`，保存返回的块 ID 和原 span；
随后用 `parser.parse_raw_block(raw)` 展开保存的默认 token。该重载不推进自定义 parser 的 cursor，
消费自定义 token 仍由调用方负责。块 ID 和 span 不能拼造或跨源码复用。

## 构造列表与回溯

使用 `parser.list<T>()` 创建语法句柄列表，随后调用 `append`、`len`、`at`。
构造方法支持列表与原有切片参数混用；只接受支持的语法句柄，不是通用容器。

下面是 `parse` 方法中已有 `parser` 和 `input` 后的构造片段：

```c
_ statements = parser.list<std.jiang.syntax.Stmt>();
_ span = input.name_span;
_ value = parser.int_literal(span, "42");
statements.append(parser.return_statement(span, value));
_ body = parser.block(span, statements);
```

试探解析前保存 `parser.checkpoint()`，需要换一种解析方式时调用 `parser.rewind(saved)`。
它恢复 token 位置、诊断、AST 和受管理列表，也撤销对已有节点附着的 Attribute。
保存点之后创建的节点与列表句柄在回退后失效；保存点之前的列表恢复到原内容。
成功解析后直接继续，不需要 commit。

Provider 自己的字段、普通 Vector 和外部副作用不随回溯撤销。需要自动恢复的待附着 Attribute
应放在 parser 管理列表中。默认扫描 token 可以重复解析；自定义扫描结果也应保证重试时可再次读取。

默认 token 用 `single_quoted`／`double_quoted` 区分引号。SymbolId 是解码后的文本，
原始引号和转义可从 span 对应源码读取。构造 Jiang 字符 AST 时必须是单个 Unicode 标量。
