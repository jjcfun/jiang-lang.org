函数声明先写返回类型，然后是函数名、参数和函数体。

```c
Int add(Int left, Int right) {
    return left + right;
}
```

## 返回类型

函数总是有返回类型。没有有意义的返回值时使用 `()` 表示单元类型：

```c
() log_done() {
    print("done");
    return ();
}
```

## 参数

参数列表中每个参数写成 `类型 名字`。参数可以带默认值；带默认值的参数必须位于参数列表尾部。
当前默认值只支持字面量，并按参数的期望类型检查：

```c
Int scale(Int value, Int factor = 2) {
    return value * factor;
}

Int result = scale(21, 2);
Int defaulted = scale(21);
```

调用实参可以直接按位置提供，也可以写成 `name: expr`。位置参数必须出现在命名参数之前；
命名参数可以重排，也可以跳过带默认值的参数：

```c
Int value = scale(21, 2);
Int named = scale(value: 21, factor: 2);
Int reordered = scale(factor: 2, value: 21);
Int defaulted = scale(value: 21);
```

命名参数之后不能再出现位置参数：

```c
Int bad = scale(value: 21, 2); // 错误：命名参数后不能再写位置参数。
```

命名参数按参数名匹配，因此可以和函数声明里的参数顺序不同。省略的默认参数会在调用前补上。

## 默认参数和重载

如果一个名字有多个重载，调用时会根据实参数量、参数名字和参数类型选择匹配的函数。默认参数
参与重载歧义检查：如果两个 overload 在同一调用点可能同时满足参数数量和参数类型，必须诊断为歧义。

```c
Int f(Int value) {
    return value;
}

Int f(Int value, Int extra = 1) {
    return value + extra;
}

Int a = f(10); // 错误：两个 overload 都可以匹配。
```

这类函数应该改成不同名字，或让参数类型/数量不重叠。

## 局部声明、value block 和返回

函数体是一个代码块。局部变量声明以类型开头；可以用 `return` 显式返回：

```c
Int abs(Int value) {
    if value < 0 {
        return -value;
    } else {
        return value;
    }
}
```

`return` 是语句，不是普通表达式。显式返回 `()` 时需要写出单元值：

```c
() done() {
    return ();
}
```

代码块可以作为 value block 使用。`stmt` 不贡献 block 的值；block 的值只来自最后一个不带分号的
tail expression。没有 tail expression 的 block 值为 `()`：

```c
Int value = {
    Int base = 40;
    base + 2
}

() unit_value = {
    Int ignored = 1;
}
```

函数体本身也是 block，因此函数体末尾的 tail expression 可以作为函数返回值。下面两种写法等价：

```c
Int add(Int left, Int right) {
    return left + right;
}

Int add_tail(Int left, Int right) {
    left + right
}
```

需要提前返回、从分支里直接退出，或者返回 `()` 时，继续使用 `return`。

## 多返回值

可以使用元组返回多个值：

```c
(Int, Int) split(Int value) {
    return (value, value + 1);
}

Int main() {
    (_ left, _ right) = split(41);
    return left + right;
}
```

`(T)` 与 `T` 等价；一元元组不会形成独立的运行时形态。

## 泛型函数

泛型参数写在函数名之后：

```c
T id<T>(T value) {
    return value;
}

@where(T: Numeric)
T add<T>(T left, T right) {
    return left + right;
}
```

`@where(...)` 是约束注解，写在泛型声明之前。

## 方法

类型里的函数分为实例方法和不带 `self` 参数的关联函数。

```c
struct User {
    Int id;

    User zero() {
        return User(id: 0)
    }

    Int value() {
        return self.id;
    }
}

User user = User(id: 42)
Int a = user.value();
User z = User.zero();
```

实例方法体内有隐式 `self`。不带接收者的关联函数不能使用 `self`。

`init(...)` 是构造函数，拥有初始化中的 `self` 目标，只能通过 `Type(...)` / `new Type(...)`
调用，不作为普通函数值暴露。`deinit()` 是资源清理入口，不能手动当作普通函数调用。

实例方法可以用两种方式调用：

```c
Int a = user.value();
Int b = User.value(user$.ref());
```

第二种形式把接收者引用作为第一个参数传入，适合需要把方法当作函数值保存或传递的场景。

## 函数值和闭包

Jiang 区分 C 风格函数指针和闭包：

- `RawFn<R, A, B, ...>` 是裸函数指针，不带捕获环境。需要 C ABI callback 时使用它。
- `Fn<R, A, B, ...>` 是 Jiang 闭包值。它可以捕获局部值，也可以包装匹配的 `RawFn`。
- `Fn<R, A, B, ...>^` 是拥有型闭包 handle。闭包需要离开当前栈帧时使用它。

第一个类型参数是返回类型，后续参数是调用参数类型。

```c
Bool less(Int left, Int right) {
    return left < right;
}

RawFn<Bool, Int, Int> raw_compare = less;
Fn<Bool, Int, Int> compare = Fn(raw_compare);
Bool ok = compare(1, 2);
```

匿名函数会使用上下文里的 expected type：

```c
Fn<Int, Int> add_base(Int base) {
    Fn<Int, Int> add = (value) => value + base;
    return add$.move(); // 错误：stack Fn 不能让捕获的栈环境逃逸。
}
```

栈上的 `Fn` 可以 move，但不能 copy。它可以传给立即调用的函数，但不能返回，也不能保存到可能
比捕获的栈变量活得更久的位置。

使用 `new` 创建拥有型闭包：

```c
Fn<Int>^ make_answer(Int value) {
    return new () [_ snapshot = value] => snapshot;
}

Int main() {
    Fn<Int>^ answer = make_answer(42);
    return answer() - 42;
}
```

`Fn^` 可以直接调用。如果 pattern matching 或字段访问拿到的是拥有型闭包 handle 的引用，
需要先借成 callable view：

```c
Int call_optional(Fn<Int>^? maybe) {
    guard maybe is .some(ref _ answer_ref) else {
        return 0;
    }
    Fn<Int>& answer = answer_ref$.ref();
    return answer();
}
```

实例方法作为未绑定函数值时，接收者展开为第一个参数，并表示成 `RawFn`：

```c
RawFn<Int, User&> get_value = User.value;
Int value = get_value(user$.ref());
```

`unsafe` 可以写在 `RawFn<...>` 或 `Fn<...>` 的返回类型前，表示调用这个值需要对应上下文。
它不修饰返回值类型本身，而是修饰外层 callable 类型：

```c
RawFn<unsafe Int, Int>[]& unsafe_callbacks;
```

调用带 `unsafe` effect 的函数需要显式 effect context：

```c
Int value = unsafe {
    unsafe_callback(1)
};
```

## 异步函数和 Task

`async` 函数是无栈协程。在异步上下文中调用它时，调用点会隐式挂起直到结果可用，因此调用表达式
直接表现为声明的返回类型：

```c
async Int load_page() {
    1
}

async Int render() {
    load_page() + 1
}
```

0.4.7 的 async 能力属于具名函数和直接调用；async `Fn` 值与 async 闭包尚未进入受支持的
callable value API。

使用 `async call(...)` 或 `async { ... }` 可以立即启动任务并得到 body-local `Task<T>`。
调用 `await()` 会消费该 Task。先启动多个 Task，再按源码顺序等待，仍然可以保持并发推进：

```c
async Int load_both() {
    Task<Int> left = async load_left();
    Task<Int> right = async load_right();
    left.await() + right.await()
}
```

`Task<T>` 不能出现在参数、返回类型、字段、全局变量或 public ABI 中。
`task.await()` 和 `task.cancel()` 都会消费 Task，只能二选一。取消会等待 Task 进入终态并完成
coroutine frame 清理；未消费 Task 直接离开作用域表示 detach，不会隐式取消。持有非 static
borrow 的 Task 必须在 source 离开作用域前显式消费。

Domain effect 使用实现 `Domain` 的类型所对应的命名 `const` value。即使类型和值相同，
两个不同 const binding 也表示两个不同 Domain：

```c
struct WorkerDomain: Domain<kind = .concurrent> {}
const WorkerDomain worker = WorkerDomain();

async [worker] Int load_on_worker() {
    1
}
```

`async [worker] { ... }` 在该 Domain 上启动 Task；无 domain 的 async block 继承 current Domain。
在 async 函数中，`sync [worker] { ... }` 是结构化 Domain switch：它挂起当前 coroutine，不阻塞
worker thread，完成后回到进入前的 Domain。普通函数最外层的 `sync [worker]` 才会阻塞调用线程。

底层 async API 可以用 `coroutine.suspend(registration)` 主动挂起。registration callback 会收到
continuation；完成时调用 `resume(value)`，需要主动取消时使用 `on_cancel(handler)` 注册处理。
取消已经 claim operation 后，迟到 resume 会自动失效。

需要 ABI 级函数指针时使用 `RawFn`。普通 callback API 如果希望接收捕获闭包，应使用 `Fn`。
