函数声明先写返回类型，然后是函数名、参数和函数体。

```c
Int add(Int left, Int right) {
    return left + right;
}
```

## 返回类型

函数总是有返回类型。没有有意义的返回值时使用 `()` 表示单元类型：

```c
() log_done() {
    print("done");
    return ();
}
```

## 参数

参数列表中每个参数写成 `类型 名字`。默认参数可以出现在参数列表任意位置。当前默认值只支持
字面量，并按参数的期望类型检查：

```c
Int scale(Int factor = 2, Int value) {
    return value * factor;
}

Int result = scale(2, 21);
Int defaulted = scale(value: 21);
```

调用实参可以直接按位置提供，也可以写成 `name: expr`。位置参数总是绑定最早尚未绑定的参数，
不会根据实参类型跳过默认参数。命名参数可以重排，也可以跳过带默认值的参数：

```c
Int value = scale(2, 21);
Int named = scale(factor: 2, value: 21);
Int reordered = scale(value: 21, factor: 2);
Int defaulted = scale(value: 21);
Int missing = scale(21); // 错误：21 绑定 factor，value 仍然缺失。
```

命名参数之后不能再出现位置参数：

```c
Int bad = scale(value: 21, 2); // 错误：命名参数后不能再写位置参数。
```

命名参数按参数名匹配，因此可以和函数声明里的参数顺序不同。省略的默认参数会在调用前补上。

## 默认参数和重载

如果一个名字有多个重载，调用时会根据实参数量、参数名字和参数类型选择匹配的函数。默认参数
参与重载歧义检查：如果两个 overload 在同一调用点可能同时满足参数数量和参数类型，必须诊断为歧义。

```c
Int f(Int value) {
    return value;
}

Int f(Int value, Int extra = 1) {
    return value + extra;
}

Int a = f(10); // 错误：两个 overload 都可以匹配。
```

这类函数应该改成不同名字，或让参数类型/数量不重叠。

## 局部声明、value block 和返回

函数体是一个代码块。局部变量声明以类型开头；可以用 `return` 显式返回：

```c
Int abs(Int value) {
    if value < 0 {
        return -value;
    } else {
        return value;
    }
}
```

`return` 是语句，不是普通表达式。显式返回 `()` 时需要写出单元值：

```c
() done() {
    return ();
}
```

代码块可以作为 value block 使用。`stmt` 不贡献 block 的值；block 的值只来自最后一个不带分号的
tail expression。没有 tail expression 的 block 值为 `()`：

```c
Int value = {
    Int base = 40;
    base + 2
}

() unit_value = {
    Int ignored = 1;
}
```

函数体本身也是 block，因此函数体末尾的 tail expression 可以作为函数返回值。下面两种写法等价：

```c
Int add(Int left, Int right) {
    return left + right;
}

Int add_tail(Int left, Int right) {
    left + right
}
```

需要提前返回、从分支里直接退出，或者返回 `()` 时，继续使用 `return`。

## 多返回值

可以使用元组返回多个值：

```c
(Int, Int) split(Int value) {
    return (value, value + 1);
}

Int main() {
    (_ left, _ right) = split(41);
    return left + right;
}
```

`(T)` 与 `T` 等价；一元元组不会形成独立的运行时形态。

## 泛型函数

泛型参数写在函数名之后：

```c
T id<T>(T value) {
    return value;
}

@where(T: Numeric)
T add<T>(T left, T right) {
    return left + right;
}
```

`@where(...)` 是约束注解，写在泛型声明之前。

## 方法

类型内部函数如果没有 receiver，就是关联函数。readonly `Self&` receiver 简写为 `self`：

```c
struct User {
    Int id;

    User zero() {
        return User(id: 0)
    }

    Int value(self) {
        return self.id;
    }
}

User user = User(id: 42)
Int a = user.value();
User z = User.zero();
```

receiver 必须显式出现在参数列表中。`Ret method(self, ...)` 使用 `Self&`；
`Ret method(Self&! self, ...)` 要求 unique mutable receiver；
`Ret method(Self self, ...)` 按值消费 receiver。不带 receiver 的函数是关联函数。

`init(self, ...)` 是构造函数，拥有初始化中的 `self` 目标，只能通过 `Type(...)` /
`new Type(...)` 调用，不作为普通函数值暴露。`deinit(self)` 是资源清理入口，
不能手动当作普通函数调用。

实例方法可以用两种方式调用：

```c
Int a = user.value();
Int b = User.value(user$.ref());
```

第二种形式把接收者引用作为第一个参数传入，适合需要把方法当作函数值保存或传递的场景。

## 函数值和闭包

Jiang 区分 C 风格函数指针和闭包：

- `RawFn<R, A, B, ...>` 是裸函数指针，不带捕获环境。需要 C ABI callback 时使用它。
- `Fn<R, A, B, ...>` 是 Jiang 闭包值。它可以捕获局部值，也可以包装匹配的 `RawFn`。
- `Fn<R, A, B, ...>^` 是拥有型闭包 handle。闭包需要离开当前栈帧时使用它。

第一个类型参数是返回类型，后续参数是调用参数类型。

```c
Bool less(Int left, Int right) {
    return left < right;
}

RawFn<Bool, Int, Int> raw_compare = less;
Fn<Bool, Int, Int> compare = Fn(raw_compare);
Bool ok = compare(1, 2);
```

匿名函数会使用上下文里的 expected type：

```c
Fn<Int, Int> add_base(Int base) {
    Fn<Int, Int> add = { value => value + base };
    return add; // 错误：被 move 的 stack Fn 不能让捕获的栈环境逃逸。
}
```

零参数闭包以 `{ =>` 开头。显式 capture list 写在参数之前，并且只能选择已有 local：
`[name]` 按值捕获，`[ref name]` / `[ref! name]` 分别建立共享/独占借用。capture list
不能声明、重命名、标注类型或初始化变量。需要捕获快照或表达式结果时，
先声明普通 local：

```c
Int snapshot = value;
Fn<Int, Int> add_snapshot = { [snapshot] delta => snapshot + delta };
```

未列入列表的 local 默认按共享 view 捕获；raw pointer 是按值捕获的例外。需要写入外层 storage
时，必须显式使用 `[ref! name]`。

最后一个参数是 `Fn` 或 `RawFn` 时，可以把它写成尾随闭包：

```c
() run(Fn<()> work) {
    work();
}

run { print("done"); };
map(values) { value => transform(value) };
```

在尾随位置，`{ statements }` 表示零参数闭包。单独出现的 brace body 仍是普通 block；
单独写零参数闭包时需要 `=>`。一次调用只接受一个尾随闭包，前面省略的参数必须有默认值，并通过
命名参数跳过。

栈上的 `Fn` 可以 move，但不能 copy，因此普通按值使用默认执行 move。它可以传给立即调用的函数，
但不能返回，也不能保存到可能比捕获的栈变量活得更久的位置。

使用 `new` 创建拥有型闭包：

```c
@life()
Fn<Int>^ make_answer(Int value) {
    return new { [value] => value };
}

Int main() {
    Fn<Int>^ answer = make_answer(42);
    return answer() - 42;
}
```

`Fn^` 可以直接调用。如果 pattern matching 或字段访问拿到的是拥有型闭包 handle 的引用，
需要先借成 callable view：

```c
Int call_optional(Fn<Int>^? maybe) {
    guard maybe is .some(ref answer_ref) else {
        return 0;
    }
    Fn<Int>& answer = answer_ref$.ref();
    return answer();
}
```

实例方法作为未绑定函数值时，接收者展开为第一个参数，并表示成 `RawFn`：

```c
RawFn<Int, User&> get_value = User.value;
Int value = get_value(user$.ref());
```

`unsafe` 可以写在 `RawFn<...>` 或 `Fn<...>` 的返回类型前，表示调用这个值需要对应上下文。
它不修饰返回值类型本身，而是修饰外层 callable 类型：

```c
RawFn<unsafe Int, Int>[]& unsafe_callbacks;
```

调用带 `unsafe` effect 的函数需要显式 effect context：

```c
Int value = unsafe {
    unsafe_callback(1)
};
```

## 异步函数和 Task

`async` 函数是无栈协程。在异步上下文中调用它时，调用点会隐式挂起直到结果可用，因此调用表达式
直接表现为声明的返回类型：

```c
async Int load_page() {
    1
}

async Int render() {
    load_page() + 1
}
```

async 函数、async `RawFn` 值和 async `Fn` 闭包使用同一套调用与挂起模型。闭包可以捕获环境；
capture 仍遵守普通的所有权、生命周期与跨 Domain `Sendable` 规则。

使用 `Task { ... }` 可以在当前 Domain 立即启动任务；需要显式选择 Domain 时写
`Task(domain: worker) { ... }`。结果是地址稳定的 `Task<T>`。这种直接形式属于结构化任务且为
`!Movable`，因此留在当前作用域内。它也可以直接存入 struct、tuple 或固定数组中的静态字段；
包含它的聚合值同样不能移动、按值传参、返回或捕获。先启动多个 Task，再按源码顺序等待，
仍然可以保持并发推进：

```c
async Int load_both() {
    Task<Int> left = Task { load_left() };
    Task<Int> right = Task { load_right() };
    left.await() + right.await()
}
```

需要让 Task 独立移动、返回、传参或存入可移动字段/容器时，使用 `new Task { ... }` 或
`new Task(domain: worker) { ... }`。
结果类型是可移动但不可复制的 `Task<T>^`；移动只转移 owner pointer，不会搬动正在运行的 Task：

```c
@life()
Task<Int>^ start_load() {
    new Task(domain: global_domain) { load_page() }
}

@region(a)
struct Request {
    @life(a)
    Task<Int>^ task;
}
```

`Task<T>^` 与直接 `Task<T>` 使用同一 capture lifetime shape；`^` 只改变存储所有权，不改变
借用关系。不携带参数 borrow 的工厂使用 `@life()`；返回捕获了借用的 owner 时，用
`@life(return: source)` 声明来源；Task owner 字段通过 struct 的 `@region` 绑定 lifetime。
owner 析构不会等待，因此携带 capture loan 的 owner 必须先通过 `await()` 或
`cancel_and_await()` 消费，不能直接 drop。

`task.await()` 会等待并且只能消费一次结果。`task.cancel()` 是同步、幂等的取消请求：它不会等待，
也不会消费结果，因此之后仍可调用 `await()`。`task.cancel_and_await()` 会请求取消并异步等待 Task
退出。销毁 `Task<T>^` owner 不会阻塞，也不会隐式取消；owner 与 coroutine 都不再使用 Task 后，
runtime 才回收存储。直接 `Task<T>` 仍保持结构化；外层作用域退出时，
会先取消未完成 child，
再等待它们结束，最后才析构其余 local。

取消是协作式的。挂起和恢复边界会自动观察请求；长时间不挂起的计算应定期调用
`coroutine.check_cancelled()`。没有请求时它立即返回，有请求时当前 coroutine 直接进入 cleanup。
普通 `await()` 如果发现 child 已因取消结束，会同时取消当前 parent；结构化 cleanup 随后取消并等待
其他未完成 sibling。需要只停止指定 Task、然后继续执行 caller 时，使用 `cancel_and_await()`。

Domain effect 指定异步工作在哪里运行。通常先使用两个标准 Domain：

```c
async [global_domain] Int load_on_worker() {
    1
}

Int main() {
    coroutine.sync(main_domain) {
        Task<Int> worker = Task(domain: global_domain) {
            load_on_worker()
        };
        worker.await()
    }
}
```

`main_domain` 是绑定程序启动线程的串行 Domain，`global_domain` 使用进程共享的并发执行器。
`Task(domain: global_domain) { ... }` 在该 Domain 上启动 Task；`Task { ... }` 继承 current Domain。
已删除的 `async { ... }` 和 `sync [domain] { ... }` block 形式不再接受。
`coroutine.sync(domain) { ... }` 的 Domain 参数始终必填。在 async 函数中，它挂起当前
coroutine，在目标 Domain 执行 closure，不阻塞 worker thread，完成后回到进入前的 Domain。
普通函数最外层的 `coroutine.sync(main_domain)` 会阻塞调用线程，同时泵送主线程工作。

跨 Domain 按值传递的值既要保持原本的 move/copy 能力，也必须满足 `Sendable`。当 `T: Sendable`
时，共享 `T&` 可以跨 Domain，但普通 lifetime 仍不能超过来源 owner。唯一 `T&!` 不直接跨
Domain；它可以 reborrow 为 `T&`，并在 shared reborrow 存活期间冻结原 unique reference 的写能力。
raw pointer 不会自动满足 `Sendable`。

应用如果有自己的队列或事件循环，可以实现 Executor，再把它绑定到 Domain：

```c
struct InlineExecutor: Executor {
    () enqueue(Self& self, ExecutorJob job) {
        job.run();
    }
}

struct InlineDomain: Domain<kind = .serial> {
    associated ExecutorType = InlineExecutor;

    InlineExecutor make_executor(Self& self) {
        InlineExecutor()
    }
}

const InlineDomain inline_domain = InlineDomain();
```

每个命名 `const` binding 都是独立 Domain，并且只懒创建一个 Executor 实例。
`ExecutorJob` 是只能移动、只能运行一次的值；Executor 接收后必须最终恰好调用一次 `run()`。
`enqueue` 可能从多个线程并发调用，Executor 必须自行同步可变队列状态。

支持 lock-free 的简单标量共享状态使用 `Atomic<T>`。默认操作采用 sequential order；需要更弱
顺序时，向同名重载传入 `MemoryOrder`：

```c
Atomic<Int> state = Atomic<Int>(0);
state.set(1, .release);
Int observed = state.get(.acquire);
Int previous = state.get_and_set(2, .acquire_release);
Bool changed = state.compare_and_set(
    2, 3, MemoryOrder.acquire_release, MemoryOrder.acquire
);
```

复合共享状态使用 `Mutex<T>`。`Mutex<T>` 地址稳定且为 `!Movable`；当 `T: Sendable` 时，
跨 Domain 移动 `Mutex<T>^` owner handle。`with_lock` 只在同步 callback 中提供 unique
mutable reference，因此不能把锁持有到 `await` 之后。

底层 async API 可以用 `coroutine.suspend(registration)` 主动挂起。registration callback 会收到
continuation；完成时调用 `resume(value)`，需要主动取消时使用 `on_cancel(handler)` 注册处理。
取消已经 claim operation 后，迟到 resume 会自动失效。

需要 ABI 级函数指针时使用 `RawFn`。普通 callback API 如果希望接收捕获闭包，应使用 `Fn`。
