Jiang separates ownership, borrow kind, pointee capability, and binding mutability. Resource
movement and lifetime rules are covered in [Ownership, Borrowing & Lifetimes](/language/ownership/).

## Pointer and Reference Forms

- `T^`: an owning pointer in a readonly owner place.
- `T^!`: a writable owner place; it can replace the owner and mutate writable pointee fields.
- `T&`: a shared readonly non-owning borrow.
- `T!&`: a unique mutable non-owning borrow. It cannot be implicitly copied.
- `T&!`: a rebindable reference slot that contains a shared borrow.
- `T!&!`: a rebindable reference slot that contains a unique mutable borrow.
- `T*`: a readonly-pointee raw pointer for FFI, ABI, and low-level code.
- `T!*`: a mutable-pointee raw pointer.
- `T*!` / `T!*!`: rebindable raw-pointer places without / with pointee write capability.
- `T[]&` / `T[]!&`: shared readonly / unique mutable borrowed slices.
- `T[]^` / `T[]^!`: readonly / writable owning-slice places.
- `T[:S]&`: a borrowed sentinel slice whose sentinel value is `S`.

Only `T^` and `T[]^` express language-level ownership. Compiler-owned names behind these forms are
not available to user source; use the surface syntax directly.

The `!` before `&` or `*` belongs to the pointee capability. The outermost `!` belongs to the current
binding/place. For example, `T!&` is a unique mutable borrow, while `T&!` is a rebindable slot holding
a shared readonly borrow.

## Creating Borrows and Raw Pointers

```c
Int value = 123;
Int& shared = value$.ref();

Int! mutable_value = 123;
Int!& unique = mutable_value$.mut_ref();

Int* raw = unsafe {
    value$.ptr()
};

Int!* mutable_raw = unsafe {
    mutable_value$.mut_ptr()
};
```

`ref()` and `ptr()` never manufacture write capability. The mutable forms are `mut_ref()` and
`mut_ptr()`, and they require a writable source place. Raw-pointer creation and access remain
inside `unsafe`.

## Dereference and Member Access

`T^` can auto-dereference when the expected type is `T`; `$.get()` requests an explicit pointee read:

```c
Int^ make_value();

Int^ owner = make_value(); // preserve ownership
_ inferred = make_value(); // inferred: Int^
Int copied = make_value();  // expected Int: auto-dereference
Int explicit = owner$.get();
```

Member access can pass through an owning pointer:

```c
struct Item {
    Int value;
}

Item^ item = new Item(value: 42);
Int value = item.value;
```

References and raw pointers use `$.get()` for explicit reads. Writing requires a unique mutable
borrow or mutable-pointee raw pointer:

```c
Int! value = 0;
Int!& ref = value$.mut_ref();
ref$.set(41);

unsafe {
    Int!* raw = value$.mut_ptr();
    raw$.set(42);
}
```

## Raw Pointer Indexing

`T*` is also the unbounded raw contiguous-memory view. The old `T[*]` and `T[*:S]` spellings are
legacy compatibility syntax and should not be used by new code. Indexing is always unsafe because
the pointer carries no length:

```c
unsafe {
    UInt8* bytes = source$.ptr();
    UInt8 first = bytes[0];

    UInt8!* output = destination$.mut_ptr();
    output[1] = 42;
}
```

Use `T[]&` when the API should carry a runtime length, and `T[:S]&` when it should carry a sentinel
guarantee.

## Implicit Operation Layer

`$` prevents receiver auto-dereference and enters the implicit operation layer. Operations such as
`$.get()`, `$.set()`, `$.ref()`, `$.mut_ref()`, `$.ptr()`, `$.mut_ptr()`, and `$.move()` are covered in
[Implicit Operation Layer](/language/implicit-layer/).
